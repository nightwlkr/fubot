# Backtest: 45-Day Baseline vs Stop-Floor Correction — 2026-11-05

**Purpose**: Tasks 10/11 of `analysis/trade-loss-fix-tasks.md` — measure whether the
Phase-1 stop-floor changes (ATR multiplier 1.5→2.5, `min_risk_pct` 0.05%→0.5%)
improve net expectancy over a statistically meaningful window.

**Window**: last 45 days of closed candles ending at the last closed 5m bar
(fetched 2026-11-05; paginated via `backend/backtest_data.py`, all intervals
pinned to one `[start, end)`).

**Universe**: APEUSDT, BNBUSDT, BTCUSDT, LINKUSDT, OPUSDT, SOLUSDT, UNIUSDT —
the 7 symbols that produced the 35 production trades in
`analysis/production-trade-analysis-2026-11-05.md`. Note: the prod `symbols`
table currently has only 5 rows `enabled=true` (APT, ARB, SOL, UNI, XRP); the
scanner's enabled set was changed after the weekly halt. These runs measure the
strategy change on the universe that generated the losses, not today's enabled
set.

**Shared config** (mirrors prod settings table, verified via read-only query):
3CANDLE only (`strategy_fvg_enabled=false`, `strategy_choch_enabled=false`,
`strategy_obfvg_enabled=false`), `rr_min=3.0`,
`trade_min_trend_strength=MODERATE`, `trade_neutral_markets=true`,
`volume_filter_enabled=false`, `regime_filter_enabled=true`,
`signal_max_age_minutes=60`, `--days 45`, touch-fill entries
(`entry_penetration_bps=0` except run C).

**Fee model**: 0.11% round trip (0.045% taker ×2 + 0.01% slippage ×2,
`backend/core/cost_model.py`). `netR`/`expNetR` are the trustworthy columns;
`totalR`/`expR` are gross.

**Harness caveat**: `profit_lock_trail_r` defaults to 0.5 in the harness vs 0.75
in prod settings; identical across all three runs so the A/B comparison is
unaffected, but absolute levels may differ slightly from live.

## Verdict

**The stop-floor changes did NOT improve net expectancy on this 45-day window —
they made it worse.**

- Baseline: 472 closed trades, netR **-21.46**, expNetR **-0.045**/trade.
- Corrected: 300 closed trades (-36%), netR **-26.73**, expNetR **-0.089**/trade.
- The 1bp penetration sensitivity (run C) confirms the direction: expNetR
  -0.094, essentially unchanged — the result is not a fill-model artifact.

What the correction did achieve: it cut trade count by ~36% (the 0.5%
`min_risk_pct` floor removed the degenerate tight-stop tail that produced the
1.44R/trade fee drag in production), and per-trade cost in R fell. But wider
stops also shrink every R multiple — gross totalR fell from +26.36 to -9.20 —
and the removed tight-stop trades were, on this window, net contributors in
gross terms even after their heavy fee drag. The surviving wider-stop trades
still lose: only UNIUSDT stays positive (+1.72 netR, 32 trades — the only cell
near the 20-trade inconclusive floor; all other cells are 38-80 trades).

Per-symbol, LINKUSDT and UNIUSDT were the only net-positive cells in baseline
(+9.54, +8.05); under the corrected config LINK flips negative (-4.23) and UNI
shrinks to +1.72. BNBUSDT and BTCUSDT are negative under both configs.

**Caveats**: OHLC fills cannot model queue position (run C bounds this at 1bp —
immaterial here); the harness omits `PositionManager._check_profit_trailing_2`
and shared portfolio slots; one window of 45 days is one regime sample. This
is evidence that the Phase-1 changes reduce fee drag per trade but do not, on
this data, produce a net-positive strategy — consistent with the 2026-10-20
research note that stop-distance filters did not improve both train and
holdout windows. Deploy decision remains with the user; Tasks 12/16
(symbol-specific and regime analysis) are the natural follow-ups.

**Run log**: `/tmp/backtest_45d_runs.log` (run B first attempt died on a
transient Binance `-1007` timeout fetching OPUSDT; clean retry succeeded).

## Decomposition runs

**Purpose**: isolate which of the two Phase-1 changes caused the expectancy
regression. Runs A and B changed both knobs at once, so the attribution was
unresolved. These runs change **one knob at a time** against the same
baseline.

| Run | atr_stop_mult | min_risk_pct | Isolates |
|-----|---------------|--------------|----------|
| A — BASELINE | 1.5 | 0.0005 | (reference, unchanged) |
| D1 | 2.5 | 0.0005 | **ATR widening alone** |
| D2 | 1.5 | 0.005 | **min-risk floor alone** |
| B — CORRECTED | 2.5 | 0.005 | both (= run B above) |

Identical to runs A/B in every other respect: same 7 symbols, `--days 45`,
3CANDLE only (`--no-fvg --no-choch --no-obfvg`), `rr-min 3.0`, `--strength
MODERATE`, neutral on, volume off, touch-fill (`entry_penetration_bps=0`),
0.11% round-trip fee.

### Method note — one shared data window

`run_backtest` derives its window from `window_for_days()`, which anchors the
end to the **last closed 5m bar at wall-clock time** (`backend/backtest_data.py:149`).
Two runs separated in time therefore use slightly different windows and drift
by 1-2 trades (the same D1 config yielded 300 closed trades via the CLI and
299 in a later process). To make the comparison exact, the decomposition
replays **one fetched candle set** through four `Backtester` instances — same
window, same data, only the setting under test varies. All four rows below
come from that single-window run; the CLI D1/D2 rows were cross-checked
against it and agree.

### Why: the ATR floor subsumes the risk floor

D1 and B are **identical on every cell** (299 closed, -7.68 gross, -25.17
net, -0.084 expNetR) — the 0.5% risk floor never binds under `atr=2.5`.
Instrumenting the `min_risk_pct` check (`backend/backtest.py:493`) shows why:

| Run | candidates reaching risk check | median stop % of entry | min stop % of entry | rejected by 0.5% floor |
|-----|-------------------------------|------------------------|---------------------|------------------------|
| A | 636 | 1.341% | 0.219% | 0 |
| D1 | 414 | 2.321% | **0.541%** | **0 (0.0%)** |
| D2 | 646 | 1.329% | 0.219% | 42 (6.5%) |
| B | 414 | 2.321% | **0.541%** | **0 (0.0%)** |

At `atr=2.5` the ATR-derived stop is **already at least 0.541% of entry** on
every setup that reaches the risk check — above the 0.5% threshold — so the
risk floor has nothing left to remove and D1 ≡ B. The two Phase-1 changes are
**not additive**: the ATR widening already delivers the floor's exclusion, so
combining them adds nothing beyond the ATR change itself. The 42 rejections
the floor does make at `atr=1.5` are all stops between 0.219% and 0.495% of
entry — exactly the degenerate tail the floor was written to remove.

(D2 reaches the check with 646 candidates against A's 636. That is not
measurement noise: `min_risk_pct` cannot affect candidate *generation*, only
the final filter — but a rejected candidate opens no position, so the
symbol's one-position busy-lock (`backend/backtest.py:643`) frees up later
scan bars that A spends blocked behind a trade D2 never takes.)

The ATR change did what it was meant to do on fees and paid for it elsewhere:

| Metric | A | D1 | D2 |
|--------|---|---|---|
| median fee drag (R/trade) | 0.080 | **0.047** | 0.079 |
| median stop % of entry | 1.369% | 2.365% | 1.399% |
| win rate | 37.2% | 32.4% | **38.2%** |
| gross totalR | +27.46 | -7.68 | **+30.75** |
| netR | -20.29 | -25.17 | **-11.00** |

Widening the stop cut fee drag per trade by ~42% (0.080 → 0.047 R) — the
intended effect. But because every R multiple is scaled by a wider denominator
and the TP sits proportionally farther away, gross R collapsed from +27.46 to
-7.68 on 36% fewer trades, and win rate fell 37.2% → 32.4%. The wider stop
made each trade cheaper to hold and each winner smaller to collect.

D2 is the informative result: the risk floor **alone** improved net expectancy
(-0.043 → -0.025 expNetR, netR -20.29 → -11.00) by removing exactly the 42
degenerate tight-stop setups whose fee drag swamped their edge — stops
between 0.219% and 0.495% of entry, the tail the floor was written to cut.

### Verdict

1. **The ATR widening is the sole cause of the regression, and the min-risk
   floor is not additive with it** — D1 (ATR alone) is bit-identical to the
   corrected run B on every cell, so at `atr=2.5` the 0.5% floor binds on
   0.0% of candidates and the combined change adds nothing the ATR change did
   not already do.
2. **The min-risk floor on its own helped** (-0.043 → -0.025 expNetR, netR
   -20.29 → -11.00, +9.30 netR), confirming the production forensic finding
   that sub-0.5% stops were fee-drag casualties; the harm came entirely from
   the ATR multiplier, which cut fee drag per trade by 42% but shrank every R
   multiple and collapsed gross R from +27.46 to -7.68.
3. **The ATR widening was reverted; the min-risk floor was kept** — D2
   (atr 1.5 + min-risk 0.5%: 448 closed, netR -11.00, expNetR -0.025) is the
   best of the four configurations and is what the code now ships
   (`atr_stop_mult = 1.5`, `min_risk_pct` default 0.005). Note this remains a
   *less negative* strategy, not a net-positive one, so the deploy decision
   stays with the user.

**Caveats**: same harness omissions as the runs above (no queue/partial
fills, no `_check_profit_trailing_2`, no shared portfolio slots); one 45-day
window is one regime sample; every per-symbol cell here clears the 20-trade
inconclusive floor (D1: 32-50 closed trades per symbol, 299 across the 7);
the ATR/risk-floor interaction is a property of this window's volatility
regime and may differ where ATR/price falls below 0.2%.

**Run log**: `/tmp/backtest_45d_decomp.log` (CLI runs D1/D2, both succeeded on
the first attempt); shared-window replay and instrumentation scripts were
throwaways under `/tmp/` (`fubot_decomp_shared_window.py`,
`fubot_minrisk_probe.py`, `fubot_decomp_diag.py`).
